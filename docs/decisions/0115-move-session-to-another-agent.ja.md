# 0115. セッションを LLM なしで別種別のエージェントへ移す：会話を描画したファイルを最初のプロンプトで指す

- Tracking: #2182。#2183（共通の Markdown レンダラー `transcript.Markdown`）の上に作る。
- See also: [0039](0039-fork-at-message.ja.md)（分岐。同じ種別のみ）／
  [0049](0049-session-changed-files.ja.md)（変更ファイル一覧）／

## Context

エージェントの利用上限に達したセッションは、窓が解除されるまで止まる。週次の上限なら数日になる。
別の場所で続ける方法は二つあるが、どちらも足りない。

- **別のエージェントへ引き継ぐ**は、オペレーターのアシスタントに元セッションを読ませて要約を書かせる。
  これは LLM 呼び出しなので要約側も上限に当たり得るし、情報が落ちるし、何が残るかはオペレーターの
  判断次第になる。
- **分岐**（ADR 0039）は会話を丸ごと運ぶが、同じ種別にしか行けない。その種別こそが今使い切ったものだ。

P1（#2183）で、会話を読めるすべての種別に、正規化済みの `transcript.Turn` から Markdown への
レンダラーが 1 本でき、秘密情報はレイアウト前にマスクされるようになった。この記録は、そのファイルを
**別の**種別のセッションの出発点にする方法を決める。

### 種別ごとに今の転写から取れるもの

develop（2026-10-15）の `Agent.Transcript`／`claude.CollectAllTurns` を読んだ結果。ツール出力の上限は
レンダラーではなくパーサーが掛けている。

| 種別 | 読み元 | 履歴全体か | ツール出力 | 利用上限の検知（`limited`） |
|---|---|---|---|---|
| claude | `CollectAllTurns` 経由のセッション jsonl | はい。コンテキスト圧縮の要約も含む | 全文 | あり |
| codex | rollout | はい | 4000 文字で切る | managed のみ |
| opencode | SQLite ストア | はい | 4000 文字で切る | なし |
| cursor | TUI：転写ファイル。**managed：ドライバーのメモリ** | managed：**停止すると空** | 4000 で切る | なし |
| kiro | managed：動作中はメモリ、その後は v2 JSONL | はい | 4000 で切る | なし |
| agy | 会話 jsonl（＋保留中の質問は DB プローブ） | はい | パーサー独自 | なし |
| copilot | `events.jsonl` | はい | 4000 で切る | なし |
| lcpp | 自前のストア | はい | 4000 で切る | なし |
| muse | 自前のストア＋コメンタリーのログ | はい | パーサー独自 | あり |
| shell／ssm | なし | — | — | — |

ここから二つのことが言える。移動は `CanTranscript` のすべての種別で提供するが、`limited` から
移動を**きっかけとして出せる**のは claude・managed の codex・muse だけ。そして managed の cursor
セッションは、ハンドルが生きているうちに移さなければならない。会話がほかのどこにも無いからだ。

## Decisions

1. **引き継ぎは、移動先が読むファイルで行い、最初のプロンプトでそのファイルを名指しする。** Agent が
   元セッションを描画して書き出し、ファイルの場所・中身・何より先に冒頭を読むことを伝える短い
   プロンプトで移動先を起動する。会話は途中で一度も LLM を通らない。
2. **不採用：移動先 CLI の保存形式を合成する。** どのストアも非公開で版ごとに変わる契約で
   （opencode v2 のストアはスキーマを丸ごと置き換えた）、claude の thinking ブロックは署名付きなので、
   合成した履歴は拒否されるか、thinking 抜きで黙って再生される。安全な範囲ではすでに分岐がこれを
   やっている：同じ種別の中で、CLI 自身の分岐 API を通して。
3. **不採用：最初のターンで履歴を全部送る。** コンテキストの小さいモデル（lcpp）ではあふれるし、
   最初のターンの費用が履歴の長さに比例する。ファイルなら、移動先は冒頭を読み、必要なときだけ
   残りを読みに行ける。
4. **不採用：LLM による要約。** それは既存の引き継ぎそのもの。要約が欲しいときのために残し、
   移動はその隣に置く決定的な代替とする。
5. **同じ種別は移動先に出さない。** 移動は種別を離れるためのもの。同じ種別の中なら分岐のほうが
   多くを運ぶ（ネイティブの履歴、thinking、ツールの状態）。ダイアログは代わりに分岐を案内する。
6. **ファイルの構成：状態が先、履歴が後。** 最初の 1 画面しか読まない移動先でも、何をすべきかが
   分かっていなければならない。順に：
   1. ヘッダー：元セッション、種別、モデル、作業フォルダ、ブランチ、移動した時刻。そして
      「このファイルが記録のすべてで、元セッションのファイルは開かないこと」という一文。
   2. **止まった地点**：最後のユーザー発言（全文）、最後のアシスタントの本文、未回答の質問があれば
      それ、最後のターンが上限で切られたかどうか。
   3. 移動した時点の**作業コピーの状態**：`git status --porcelain`、差分の統計、上流より先にある
      ブランチのコミット。
   4. セッションの**変更ファイル**（ADR 0049 の一覧、Agent 側での集計）。
   5. **開いている糸**：元セッションが起こした子セッションとその状態、元セッションの保留中の
      handoff 提案を名前で（決定 12）。
   6. **会話**。`transcript.Markdown` で描画し、決定 7 で圧縮する。
7. **移動先が続けるのに要るものを残し、残りは落とす。** 各パートへの問いは「それが無いと移動先の
   行動が変わるか」であって「それが起きたか」ではない。規則はパートの種類と位置による機械的なもので、
   LLM も重要度の推測も使わない。
   - **全文で残す：** ユーザー発言（意図）、質問とその回答、計画、ピア・オペレーターからのメッセージ、
     コンテキスト圧縮の要約、アシスタントの本文。
   - **1 行で残す：** 編集系のツール呼び出し（動詞とファイル。差分は作業コピーにあり、決定 6.3 と 6.4
     が一覧にしている）、`error` パート、委任（指示と結果。サブエージェントのツール呼び出しは除く）。
   - **落とす：** thinking とサイドチェーン（P1 と同じ）、読み取り・検索・一覧など何も変えなかった
     ツール呼び出し、ツール出力、使用量・費用の行（`CostOnly`）、モデルのバッジ、Agent 自身が
     注入したプロンプト（利用上限からの再開の「続けて」など。これは元セッションへの指示で、
     移動先への指示ではない）。
   - **例外は止まった地点：** 最後の 3 ターンは、すべてのツール呼び出しを出力付きで残す
     （`ToolOutput: true`）。上限で切られたターンはたいてい調査の途中で、その出力が無ければ
     移動先は同じことをやり直す。
   - それでも 256 KiB を超えるなら、古いアシスタントの本文から順に最初の段落だけに切り詰め、
     収まるまで続ける。切った箇所には目に見える印を残す。ユーザー発言は切らない。
   - 256 KiB と 3 は出発点の値で、実測ではない。1 か所の定数にして、最初の実際の移動のあとで見直す。
   - 秘密情報は P1 と同じく必ずマスクする（`bridge.ScrubSecrets`）。
8. **ディスク上の新しい形式は作らない。メモリ上の形を 1 つ作る。** 正規化済みの `transcript.Turn` が
   すでに種別に依存しない表現で、移動先が読むファイルは Markdown にする。LLM がいちばんよく読めるのが
   Markdown だからだ。JSON の引き継ぎ形式を作ると、レンダラーと歩調を合わせ続けるべき 2 本目の契約に
   なる。その間で、Agent は `Handover` 値（決定 6 の各部。会話は決定 7 で絞り込み済み）を組み立てて
   それを描画する。絞り込みとサイズの上限は、Markdown の比較ではなくこの値に対してテストする。
   機械可読な形がいつか必要になれば、同じ値のもう一つの描画にする。
9. **ファイルは移動先の使い捨てディレクトリに置く**：`~/.af-work/<移動先>/handover-<元>.md`
   （`paths.SessionWorkDir`）。移動先が読めて、作業コピーの外なので決してコミットされず、移動先の
   セッションを削除すれば一緒に消える（`removeSessionSideFiles`）。`$AF_WORK_DIR` が設定されない
   managed の移動先でも同じで、パスは環境変数から読まずに計算する。
   このファイルは使い捨てではなく移動先の会話の一部だ。移動先は冒頭を先に読み、残りは後から読みに
   行くし、最初のプロンプトがこのパスを名指ししている。そこで、移動先をごみ箱に移すときはファイルを
   セッションと一緒にアーカイブし、復元すればファイルも戻す（`archiveSessionForDelete` に、claude の
   jsonl と同じやり方で、戻し先付きのペイロードとして足す）。これが無いと `removeSessionSideFiles` が
   `~/.af-work/<移動先>` を消し、復元した移動先はもう存在しないファイルを指すことになる。削除せずに
   停止・アーカイブするだけならファイルはそのまま残るので、手当てが要るのはごみ箱の経路だけだ。
   未解決：すべての種別が作業
   フォルダの外を確認なしで読めるか（測るべきはプランモードの cursor と kiro）。読めない場合の
   代替は、冒頭（決定 6 の 1〜5）をプロンプトに貼り、履歴だけをファイルに残すこと。
10. **移動先は同じ作業コピーで動く**（分岐と同じ）。元セッションを先に凍結する（決定 11）ので、
    二つの書き手が同時に共有することはない。`shared-working-copy` の警告は付けない。
11. **元セッションの凍結。** 移動先を起動する前に、この順で：
    1. 元セッションの meta に `movedTo: <移動先>` を記録する。`rateLimitTick` は移動済みの
       セッションを飛ばす。これが無いと、転写の末尾がまだ上限に見えるので、次の巡回が新しい
       再開を予約してしまう。
    2. 予約済みの再開を取り消し（`dropRateLimitSchedule`）、エピソードを閉じる。
    3. 元セッションを停止する。上限に達しているので失うものは無い。アーカイブはしないので、
       ミラーは読めるままで、利用者はいつでも削除できる。
    4. 移動済みのセッションを再開するときは、移動先の名前を挙げて確認を求める（「この会話は X で
       続いています」）。再開自体は許す。窓が解除されたら元に戻したい利用者もいる。
12. **持ち主は移さない。** 子セッション、元セッション宛てのピアメッセージ、保留中の handoff 提案は
    元セッションの名前のまま。これらを移すのは別の、より難しい変更になる（spawn の台帳、子の上限、
    ピアの ACL はすべて名前で引いている）。ファイルにはそれらを一覧し（決定 6.5）移動先が存在を
    知れるようにする。まだ動いている子がいれば、移動のダイアログで警告する。
13. **編集の途中で切れたターンは、移動の前に見せるだけで直さない。** ダイアログに作業コピーの
    未コミットの状態（決定 6.3 と同じデータ）を出す。決めるのは利用者で、Agent はコミットも
    stash も reset もしない。
14. **指示ファイルとスキルは写さない。** Fleet のポリシーと利用者の指示はすでにすべての種別に届いて
    いる（ADR 0042）。プロジェクトの指示ファイルは種別で違う（`CLAUDE.md` と `AGENTS.md`）ので、
    元の種別は読むが移動先の種別は読まないファイルをヘッダーに挙げ、移動先が自分で読めるようにする。
    スキルは CLI 間で翻訳しない。
15. **移動先は元 CLI の内部状態を決して読まない。** プロンプトでそう伝え、ファイルには CLI の
    ストアへのパスを載せず（ヘッダーは `TranscriptData.Path` を含めない）、移動先の入力は描画した
    ファイルだけにする。

## Phases

- **P2a — 移動。** Agent に `POST /api/sessions/{name}/move {kind, model?, driver?}`：組み立てて描画し
  （決定 6〜8）、書き出し（9）、凍結し（11）、`initial_prompt` 付きで移動先を作る（1）。CP の
  ルート許可リストにも足す。Console：セッションメニューの既存の引き継ぎの隣に項目を置き、
  ダイアログにエージェントの選択（別の種別のみ。使用量の取れる種別は `get_agent_usage` を添える）、
  未コミットの状態、動いている子セッションを出す。テスト：圧縮の上限、凍結の順序（移動後に予約が
  入らない）、停止した managed の cursor が理由付きで断られること、ごみ箱に移して復元した移動先に
  引き継ぎファイルが残っていること。
- **P2b — きっかけ。** セッションが `limited`（または `spendLimit`）を示したとき、ミラーの上限バナーに、
  枠の残っている候補付きで移動を出す。今この状態になるのは claude・managed の codex・muse だけ。
- **P2 に含めない：** 持ち主の移動（決定 12）、決定 7 の上限値を実際の移動で測ること。

## Consequences

- 上限に達したセッションを、移動先自身の最初のターンより前にモデル呼び出しを一切挟まず、
  1 回の操作で別の種別に続けさせられる。
- 移動先は元より少ないものから始まる：thinking も、ネイティブのツール状態も、最後のターンより前に
  何を読み・検索したかの記録も無い。ネイティブのストアに触れないことの代償で、同じ種別の中では
  分岐が答えであり続ける理由でもある。元が読んだファイルが必要なら移動先が読み直す。作業コピーは
  同じだ。
- 元セッションの状態は「この会話はここで止まった」を意味し続ける。単に待っているセッションと
  見分けるのは `movedTo` の印だ。
